## P19｜HTML 报告的「卡片重叠」是父卡没给内边距，不是 CSS 写错 ⚠️ 视觉坑

- 现象：评级卡内嵌的子卡片贴着父卡边框、与父卡的 `border-left` 粗色条糊在一起，
  看上去像"两个框叠在一起"，实际是 **子卡贴边 + 父卡靠 `border-left` 做强调** 两个做法互斥。
- **根因**：评级卡的正文直接挂在 `.card` 上（没有 `.cardbody` 包裹 → 没有 `padding`），
  子卡的 `margin` 直接顶到父卡边界。
- **正确做法**：
  1. **所有**卡片正文一律包在 `.cardbody{padding:...}` 里，子卡永远有安全边距；
  2. 强调色**不要**用 `border-left:4px` 画在父卡上（会和子卡边框视觉打架），
     改用 `.cardhead::before` 竖条渐变，左右上下都不越界；
  3. 子卡统一用同一个 `.sub` 组件（圆角 + 浅底 + 细边 + 左侧小竖条标题），
     `:last-child{margin-bottom:0}` 收口，避免末尾多出一截空白。
- **验证方法**：`chrome --headless=new --screenshot`（本机 Chrome 路径
  `C:/Program Files\Google\Chrome\Application\chrome.exe`）截图；要看长图就注入
  `<style>body{margin-top:-Npx !important}</style>` 分段截，或 `--print-to-pdf`。
  纯 `div` 计数校验（`<div` 与 `</div>` 数量相等）只能查结构，**查不出视觉重叠**。

## P6｜新浪 K 线是 JS 对象字面量（非严格 JSON）

- `day:` / `open:` 等键**无引号**，直接 `json.loads` 会失败。
  ```python
  import re
  txt = re.sub(r'([{,])(\w+):', r'\1"\2":', txt)
  arr = json.loads(txt)
  ```
- \(\*\) 注意正则里 `\w+` 前面的 `([{,])(\w+):` 必须**匹配非字符串内的冒号**；文中若含中文冒号无碍。

## P11｜编码问题：Git Bash heredoc 追加中文会长出坏字节

- **现象**：用 `cat >> file << 'EOF'` 追加中文到已有文件，可能插入非法 UTF-8 字节（如 `0x90`），导致整个文件被工具按 GBK 误读成乱码（`鎯呯华` = "情绪" 的 mojibake）。
- **诊断**：
  ```python
  raw = open(p,'rb').read()
  i=0; bad=[]
  while i < len(raw):
      b=raw[i]
      if b<0x80: i+=1; continue
      n = 2 if 0xC2<=b<=0xDF else 3 if 0xE0<=b<=0xEF else 4 if 0xF0<=b<=0xF4 else 0
      if n==0: bad.append(i); i+=1; continue
      try: raw[i:i+n].decode('utf-8'); i+=n
      except: bad.append(i); i+=1
  print('非法字节:', bad)
  ```
- **修复**：删掉坏字节后 `raw.decode('utf-8')` 验证并重写。
- **预防**：多行中文内容**改用文件写入工具**（Write），不要用 shell heredoc 追加。

## P12｜Windows / PowerShell 中文路径与 .bat

## P15｜腾讯 `fqkline?qfq` 会返回 HTTP 501，必须准备不复权降级链 ⚠️

- 2026-09-16 实测：`https://web.ifzq.gtimg.cn/appstock/app/fqkline/get?param=sz002093,day,,,800,qfq`
  → **`HTTPError 501: Not Implemented`**；同一主机换 `hfq` 同样失败。
- **但同主机的 `kline/kline` 仍完好**：
  `https://web.ifzq.gtimg.cn/appstock/app/kline/kline?param=sz002093,day,,,800`
  → 正常返回 800 根**不复权**日 K。
- **正确降级链**（已内置于 `ds.kline_qq`）：
  `fqkline?qfq` → `fqkline?hfq` → **`kline/kline`（不复权，501 期间仍可用）** → 新浪 `getKLineData`
- **副作用**：降级后的价格**不复权**，若区间内有分红送转，涨停价判定（`round(prev*1.1,2)`）会有误差 →
  回测数值约 ±0.1pp 偏差。**报告中必须注明当前 K 线主源。**
- 在原源上反复重试 3 次以上是浪费时间（501 不是限流，重试无用）。

## P16｜新浪 K 线 volume 单位是「股」，腾讯是「手」

## P17｜取数失败绝不能在评分/评级里静默计负分 ⚠️ 致命

- 场景：`ulist`（实时资金）被限流返回空 → 若代码把它当"资金全为 0"，则
  「主力净额 0 不算正 → −6」「净占比 0 → −4」「超大单 0 → −3」一路扣分，
  资金面被算成 **2/30**，评级从"增持"直接掉到"减持"——**与事实相反的结论**。
- **正确做法**：任一维度取不到数据 → 该维度**按中性分计入、不参与加减分**，
  并在评级卡 / 报告显式标注「数据完整度：X 维度缺失，评级置信度下降」。
- 通用原则：**数据缺失 ≠ 数据为负**。所有打分/评级模型都要做这个区分。
