## P19｜HTML 报告的「卡片重叠」是父卡没给内边距，不是 CSS 写错 ⚠️ 视觉坑

- 现象：评级卡内嵌的子卡片贴着父卡边框、与父卡的 `border-left` 粗色条糊在一起，
  看上去像"两个框叠在一起"，实际是 **子卡贴边 + 父卡靠 `border-left` 做强调** 两个做法互斥。
- **根因**：评级卡的正文直接挂在 `.card` 上（没有 `.cardbody` 包裹 → 没有 `padding`），
  子卡的 `margin` 直接顶到父卡边界。
- **正确做法**：
  1. **所有**卡片正文一律包在 `.cardbody{padding:...}` 里，子卡永远有安全边距；
  2. 强调色**不要**用 `border-left:4px` 画在父卡上（会和子卡边框视觉打架），
     改用 `.cardhead::before` 竖条渐变，左右上下都不越界；
  3. 子卡统一用同一个 `.sub` 组件（圆角 + 浅底 + 细边 + 左侧小竖条标题），
     `:last-child{margin-bottom:0}` 收口，避免末尾多出一截空白。
- **验证方法**：`chrome --headless=new --screenshot`（本机 Chrome 路径
  `C:/Program Files\Google\Chrome\Application\chrome.exe`）截图；要看长图就注入
  `<style>body{margin-top:-Npx !important}</style>` 分段截，或 `--print-to-pdf`。
  纯 `div` 计数校验（`<div` 与 `</div>` 数量相等）只能查结构，**查不出视觉重叠**。

## P11｜编码问题：Git Bash heredoc 追加中文会长出坏字节

- **现象**：用 `cat >> file << 'EOF'` 追加中文到已有文件，可能插入非法 UTF-8 字节（如 `0x90`），导致整个文件被工具按 GBK 误读成乱码（`鎯呯华` = "情绪" 的 mojibake）。
- **诊断**：
  ```python
  raw = open(p,'rb').read()
  i=0; bad=[]
  while i < len(raw):
      b=raw[i]
      if b<0x80: i+=1; continue
      n = 2 if 0xC2<=b<=0xDF else 3 if 0xE0<=b<=0xEF else 4 if 0xF0<=b<=0xF4 else 0
      if n==0: bad.append(i); i+=1; continue
      try: raw[i:i+n].decode('utf-8'); i+=n
      except: bad.append(i); i+=1
  print('非法字节:', bad)
  ```
- **修复**：删掉坏字节后 `raw.decode('utf-8')` 验证并重写。
- **预防**：多行中文内容**改用文件写入工具**（Write），不要用 shell heredoc 追加。

## P17｜取数失败绝不能在评分/评级里静默计负分 ⚠️ 致命

## P22｜盘前/竞价时段：腾讯与新浪快照返回"今日未开盘"空壳 ⚠️ 最贵的坑

- **现象**（2026-09-17 09:12 实测）：报告输出 `国脉科技 7.78 +0.00% 量比0.00`，
  明明昨日收盘是 +3.73%。
- **根因**：09:05~09:15 之间，腾讯 `qt.gtimg.cn` 会从"上一交易日收盘快照"切换为
  **"今日未开盘"空壳**：`open=0、vol=0、chg=0.00、lb=0.00、amount=0`，时间戳变成 `今日HHMMSS`。
  新浪 `hq.sinajs.cn` 同样是空壳（`今开=0.000, 昨收=7.780, 现价=0.000`）。
  > 实测同一只票：09:02 拿到的是 `20260916161457`（昨收，正确）；
  > 09:12 拿到的是 `20260917091200`（空壳）。**切换点大约在 09:05~09:10 之间。**
- **后果**：涨跌幅/量比/成交额全变 0，技术指标与所有基于 `s['chg']` 的判断全部失真。
- **对策（已实现）**：抓完快照立刻做**盘前判据** `vol<=0 or open<=0`，
  命中则用 **K 线最后一根（上一交易日）重建** 价格/涨跌/开高低/量/涨停价，
  并把 `hs/lb/amount/outer/inner/bids/asks` 置为不可用（展示 `—`），
  同时报告顶部标 `（上一交易日收盘）` 而不是 `（盘中）`。

## P23｜东财 clist 行情字段返回 `-` 占位符，`_fl("-") == 0.0` 会静默伪造数据 ⚠️

- **现象**：板块表输出「红盘数 0、涨幅中位数 +0.00%、板块主力 0.00 亿、普跌 −3 分」，
  回测/连板梯队输出「0 只」。
- **根因**：09:15 前（以及限流时）东财 `clist` 的 `f2/f3/f62` 全部返回字符串 `"-"`，
  而 `_fl("-")` → `0.0`。**接口 rc:0、行数正常，只有字段是占位符**，所以"看起来取数成功了"。
- **判断依据**：`_ok(v)`（`None` / `''` / `'-'` 判为无效）。**任何 `_fl()` 之前先过 `_ok()`。**
- **最危险的形态**：这不是报错，而是**把取数失败翻译成利空**——
  "板块普跌 −3"、"连板 0 只 → 情绪偏冷 −3"、"主力净流出 −5"，
  三者叠加能把一只票从「增持」压到「减持」。
- **对策（已实现）**：①新增 `_ok()`；②`sector_stats` 返回 `ok` 标志，无效即「按中性计、不加减分」；
  ③`board_flows` 无效时**不入表**（而不是记 0）；④`mood()` 无效时 `zl_yi=None`（绝不能是 0，
  否则 `negs` 为空 → 走"资金净流入、环境健康 +4"分支，把失败读成利好）；
  ⑤`ladder_scan` 无效时显式返回「不可用」，不输出"0 只"。
- **对照数据（同一板块 BK1215）**：错误口径 `红盘 0 / 中位 +0.00%`；
  正确口径 `130 只 / 红盘 99 / 中位 +2.07% / 涨停 7 只`。

## P24｜指数必须带显式市场前缀，裸 `000001` 是平安银行

## P26｜盘前最容易犯的错是「口径混用」：个股用昨收、板块用今日竞价

- **场景**：09:15 后东财 clist 恢复返回**今日竞价**涨幅，而个股快照因 P22 已回退到**昨日收盘**。
  两者混在一张表里算"相对强度"，得出的 pp 数完全是假的。
- **对策（已实现）**：`sector_stats(bk, pre=...)` / `mood(pre=...)` / `ladder_scan(pre=...)`
  在接受"已回退到上一交易日"的报告里**强制禁用所有实时字段**，宁可返回「不可用」。
- **代价**：盘前报告因此**只有技术面是有效的**（板块/资金/连板梯队必然缺失）。
  这是数据源的真实限制——**要完整报告请在 09:30 后（最好 10:00 后）重跑**。
  如实标注「不可用」远好过给一张看起来完整的假表。
