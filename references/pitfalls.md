## P19｜HTML 报告的「卡片重叠」是父卡没给内边距，不是 CSS 写错 ⚠️ 视觉坑

- 现象：评级卡内嵌的子卡片贴着父卡边框、与父卡的 `border-left` 粗色条糊在一起，

  `C:/Program Files\Google\Chrome\Application\chrome.exe`）截图；要看长图就注入
  `<style>body{margin-top:-Npx !important}</style>` 分段截，或 `--print-to-pdf`。

## P11｜编码问题：Git Bash heredoc 追加中文会长出坏字节

- **现象**：用 `cat >> file << 'EOF'` 追加中文到已有文件，可能插入非法 UTF-8 字节（如 `0x90`），导致整个文件被工具按 GBK 误读成乱码（`鎯呯华` = "情绪" 的 mojibake）。
- **诊断**：
  ```python
  raw = open(p,'rb').read()
  i=0; bad=[]
  while i < len(raw):
      b=raw[i]
      if b<0x80: i+=1; continue
      n = 2 if 0xC2<=b<=0xDF else 3 if 0xE0<=b<=0xEF else 4 if 0xF0<=b<=0xF4 else 0
      if n==0: bad.append(i); i+=1; continue
      try: raw[i:i+n].decode('utf-8'); i+=n
      except: bad.append(i); i+=1
  print('非法字节:', bad)
  ```
- **修复**：删掉坏字节后 `raw.decode('utf-8')` 验证并重写。
- **预防**：多行中文内容**改用文件写入工具**（Write），不要用 shell heredoc 追加。

## P22｜盘前/竞价时段：腾讯与新浪快照返回"今日未开盘"空壳 ⚠️ 最贵的坑

- **现象**（2026-09-17 09:12 实测）：报告输出 `标的甲 7.78 +0.00% 量比0.00`，

- **根因**：09:05~09:15 之间，腾讯 `qt.gtimg.cn` 会从"上一交易日收盘快照"切换为

## P23｜东财 clist 行情字段返回 `-` 占位符，`_fl("-") == 0.0` 会静默伪造数据 ⚠️

- **现象**：板块表输出「红盘数 0、涨幅中位数 +0.00%、板块主力 0.00 亿、普跌 −3 分」，
  回测/连板梯队输出「0 只」。
- **根因**：09:15 前（以及限流时）东财 `clist` 的 `f2/f3/f62` 全部返回字符串 `"-"`，
  而 `_fl("-")` → `0.0`。**接口 rc:0、行数正常，只有字段是占位符**，所以"看起来取数成功了"。
- **判断依据**：`_ok(v)`（`None` / `''` / `'-'` 判为无效）。**任何 `_fl()` 之前先过 `_ok()`。**
- **最危险的形态**：这不是报错，而是**把取数失败翻译成利空**——
  "板块普跌 −3"、"连板 0 只 → 情绪偏冷 −3"、"主力净流出 −5"，
  三者叠加能把一只票从「增持」压到「减持」。
- **对策（已实现）**：①新增 `_ok()`；②`sector_stats` 返回 `ok` 标志，无效即「按中性计、不加减分」；
  ③`board_flows` 无效时**不入表**（而不是记 0）；④`mood()` 无效时 `zl_yi=None`（绝不能是 0，
  否则 `negs` 为空 → 走"资金净流入、环境健康 +4"分支，把失败读成利好）；
  ⑤`ladder_scan` 无效时显式返回「不可用」，不输出"0 只"。
- **对照数据（同一板块 BK1215）**：错误口径 `红盘 0 / 中位 +0.00%`；
  正确口径 `130 只 / 红盘 99 / 中位 +2.07% / 涨停 7 只`。

## P27｜东财百分比字段是 ×100 存储 —— 不除 100 会印出「主力净占比 411%」

- **对策（已实现）**：内外盘改判**相对差**，`|gap| ≥ 10%` 才计 ±2，否则计 0（无信息量）。

## P29｜1 天样本推不出"连续性"

- **现象**：报告写「近 **1** 日主力负值仅 0 天，连续性良好 +5」。
- **根因**：`fflow(klt=101, lmt=12)` 当天只回 1 条，`if fd:` 即进入加分分支。
- **对策（已实现）**：`len(fd) >= 3` 才判连续性；样本 1~2 天记 0 分并注明"样本不足"。

## ★ P27~P29 的共同教训（写给未来的自己）

**① 「中性 50/100」是一个危险的数字。** 数据取不到时按基准分凑出的 50，
看起来像"多空互见、尚可接受"，实际**信息量为零**（等于什么都没说），
却比直说「数据不足、不予评级」更容易被误读成"这只票可以看看"。

**② 评级数字与文字结论打架时，必须先解决矛盾再输出。**
09-16 13:33 的午盘分析已写清「板块极强、个股跑输」「资金接的是光通信正主线，不是它这一类」，
14:42 的评级卡却给出「增持 77」。同一只票、同一天，两份材料互相打脸 —— 输出的不是分析，是混乱。

**③ 「增持 77」与次日实际走势对照（09-17 09:46 实测）**：
低开 −1.16%、缩量至昨日 2%、盘中 −2.96%、板块内排名 345/356。
**虚高的评级会直接变成交易损失**，这不是"模型误差"，是缺陷。

## P30｜主维度双缺失时必须「不予评级」，不要输出一个中性分数

- **现象**：09-17 盘中，标的甲资金面取数失败（按中性 15 计）、板块面严重跑输（10/25），
  评级输出「中性 52/100」—— 而当天它逆板块跌 2.96%、板块内排名 345/356、开盘价即全天最高。
  **评级与事实相反，且是一个很像"结论"的数字。**
- **根因**：`资金面(30) + 板块面(25) = 55 分`，占满分 55%。两者都按"基准分（=满分×50%）"计入时，
  总分必然被拉到 50 附近（= 中性档中心）。这是数学必然而非巧合：
  **缺一半的维度时，输出的"中性"不是判断，是默认值。**
- **对策（已实现）**：`score()` 增加 `no_rating` 闸门 —— 资金面与板块面**同时**缺失时，
  评级改为「数据不足」、分数位显示 `—`，只在警示框里说明原因，并引导阅读技术面/情景分析。
  单缺一个仍出评级，但保留「数据完整度」警示。
- **配套修正（同批）**：板块面相对强度扣分档位由 `−2/−5` 加密为 `−3/−6/−10`，
  `rel ≤ −2pp` 给最重档 −10（原 −5，占 25 分制仅 20%，扣不痛）。
  实测效果：同一时点标的甲由「中性 52」→ **「减持 43」**（板块面 10/25 → 1/25）。

## ★ 配套更正：封板股不能用"内盘 > 外盘 = 主动卖占优"判读

涨停价上的成交**天然记入内盘**（买方挂单在涨停价等待、卖方主动砸下来），
这是封板机制的必然结果，**不是出货信号**。

- 铁律 3 的盘口判据（内盘 >> 外盘 = 托单被动消耗）只适用于**非封板状态的横盘股**。

  但内盘 24.9 万 > 外盘 21.6 万 —— 若照搬铁律 3，会得出与事实完全相反的结论。

## P31 · 竞价只看单一时点 = 把「假高开」当接力到位

**现象（2026-09-18 实测）**：同一批昨日强势票，在集合竞价的**不可撤单段（09:20→09:25）集体被砸下来**：

| 标的 | 09:20 匹配价 | 09:25 定盘 | 漂移 |
|---|---|---|---|
| 安凯客车 000868 | +9.61% | **+1.23%** | **−8.4pp** |
| 积成电子 002339 | +9.23% | +2.55% | −6.7pp |
| 山子高科 000981 | +5.98% | +2.99% | −3.0pp |
| 三峡新材 600293 | +7.94% | +1.76% | −6.2pp |
| 海马汽车 000572 | −0.69% | −1.61% | −0.9pp |

若只截 09:20 的快照，六只里五只都落在"高开 2~6% 接力到位"甚至"接近一字"的档位；
只看 09:25 的结果，又会丢掉"它是被砸下来的"这一层关键信息。

**修法**：竞价判读**必须取两个时点**（09:20 与 09:25），**漂移量本身即判据**：
漂移 ≤ **−2pp** → 卖压主导，接力等级自动降一档（见 SKILL.md §2）。
**唯一例外**：低开票（漂移为负但绝对值小）不受此规则影响，其结论本就由价格方向决定。

## P32 · 「竞价量 ≥ 昨日 8%」未按个股成交量基数校准

**缺陷**：8% 是**相对比例**，对高换手票过严、对低换手票过松。

**实证**：山子高科 000981 昨日全天成交 **8,866 万手 / 约 26 亿元**，
8% ≈ 710 万手 / 2.1 亿元竞价成交 —— 对一只 3 元票在 09:15~09:25 的 10 分钟内达成，概率极低。
而它 09:25 实际竞价 30.6 万手（占比 3.45%）**已是本批候选中绝对量能最大的一只**。
反过来，一只日成交 20 万手的小票，8% 只有 1.6 万手，门槛形同虚设。

**修法**：改为**双轨判据**，二者满足其一即可：
1. 比例口径：竞价量 ≥ 昨日 **8%**；
2. 绝对口径：竞价额 ≥ **2,000 万元**，或竞价额进入昨日成交额的**前 3% 分位**。

**并且**：报告里必须**同时印出比例与绝对额**，不允许只给一个百分比 —— 单看百分比会让使用者
对"量到底够不够"产生系统性误判。

## P33 · 板块级加分与该股无关，把"被主线落下的票"抬成中性

**缺陷**：板块面里的「板块主力净额 ±2~4」「板块红盘率 ±1~3」是**板块级**指标，
与该股无关。板块一强，**连一只明显被落下的票也白拿 3~7 分** ——
与铁律 1/3 直接矛盾：资金没流到它身上时，板块走强对它反而是负面信号（说明钱在同方向里选了别的票）。

**实证**：600360 华微电子 09-18，半导体 179 只成分中 176 只红盘、板指 +2.46%、板块主力 +29.87 亿，
而它**排 128/179、相对强度 −0.39pp** —— 旧口径仍白送 7 分板块级加分，
板块面拿到 20/25，总评被抬到「中性 57」。

**修法**：**个股跑输同业中位数时，板块级加分一律归零**（负分照扣），
并在评级理由里逐条标注「（个股跑输同业中位数 → 该板块级加分归零）」。

## P34 · 相对强度拿了「最热的那个板块」当基准 —— 大板块中位数天然偏低

**缺陷（比 P33 更隐蔽）**：采集阶段板块按**资金规模降序**排（`_skey`），
排第一的必然是"电子（522 只）""半导体概念（540 只）"这类大盘块；
评分与渲染又直接取 `sectors[0]` 当"主线板块"算相对强度。于是：

- **大板块含大量弱势股，涨幅中位数天然偏低 → 个股只要不跌就算"跑赢"**；
- 真正对标的**细分同业**（如"分立器件"18 只）被排到后面甚至被 `sector_top=4` 截掉，
  它跑输的事实**根本不参与计分**。

结果：系统性地奖励"选中了最泛板块"的票，与铁律 1/3 的意图正好相反。

**实证（同一时点、同一只票）**：

| 基准板块 | 成分数 | 板块中位数 | 个股涨幅 | 相对强度 | 排名 | 档位 |
|---|---|---|---|---|---|---|
| 电子 BK1201（资金最大） | 522 | +1.36% | +1.23% | −0.13pp | 236/522 | 看似中性 |
| **分立器件 BK1327（同业，18 只）** | 18 | +2.13% | +1.23% | **−0.90pp** | **13/18** | **跑输 −3** |

同一只票：旧口径板块面 **22/25**（总评「中性 53」）→ 新口径 **9/25**（总评「**减持 44**」）。

**修法（缺一不可）**：
1. 新增 `pick_sectors()`：`best`＝最热相关板块（代表方向资金总量），
   `peer`＝**成分数最少**的板块（最贴近主业的细分同业）；
2. **相对强度主判据一律用 `peer`**；`sector_top` 截断时**强制把 peer 塞进样本**，
   不允许它因排序被丢弃；报告表格给 peer 行打「同业基准」标记并高亮；
3. 新增**跟风位扣分**：宽口径领先 >0 而同业跑输、且差距 ≥1pp → **额外 −3**，
   理由写明「仅靠宽口径中位数沾光」；
4. 「板块主力净额」用 `best`（方向资金总量）、「红盘率」用 `peer`（同业普涨程度）——
   两者语义不同，**不可混用**。

**推广**：凡"取一个基准做对比"的地方，都要反问一句：**这个基准是不是被排序规则挑出来的
那个"最有利解释"？** 挑最有利基准 + 只对负向维度做闸门 = 用算法的方法论给自己找台阶。
